# Цифровой двойник строительства — архитектура и статус

Этот документ описывает модуль цифрового двойника (BIM + съёмка + ГИС) и его
соответствие ТЗ «Платформа цифрового двойника строительства» v1.0.
Геологический модуль (Subsurface 3D) остался в репозитории без изменений
(`/projects/{id}`); двойник открывается по `/twin/{id}`.

## Архитектура

```
Загрузка (IFC / LAS / LAZ / E57 / OBJ / GLB / 3D Tiles ZIP / GeoJSON / KML / DXF / GeoTIFF / RVT*)
   │  потоково → объектное хранилище (MinIO / S3)
   ▼
Фоновая конвертация (apps/api/app/twin)
   ├─ IFC  → IfcOpenShell → b3dm-тайлы, 1 элемент = 1 feature (GlobalId, класс, этаж)
   │         + индекс элементов в PostgreSQL (psets, bbox, хэши для сравнения версий)
   ├─ облака точек → октодерево LOD → pnts-тайлы (потоковый просмотр)
   ├─ mesh → b3dm с текстурами; готовые 3D Tiles из Metashape/Pix4D/ContextCapture — как есть
   ├─ ГИС → GeoJSON в WGS 84 (GDAL/OGR), растр → PNG-подложка
   └─ RVT/NWD/DWG → Autodesk APS Model Derivative → IFC → далее как IFC (*при настроенном APS)
   ▼
OGC 3D Tiles 1.0, раздаются через API с проверкой доступа
   ▼
Веб-клиент (Next.js + CesiumJS): одна геопривязанная сцена для всех слоёв
```

Все 3D-данные приводятся к стандарту OGC 3D Tiles, поэтому один и тот же
вьювер стримит и BIM, и облака точек, и фотограмметрию, а сторонние тайлы
(Cesium ion, ContextCapture) подключаются без конвертации.

### Геопривязка

| Режим | Когда | Как |
|---|---|---|
| `absolute` | IFC с `IfcMapConversion`; IFC/mesh в проектных координатах и указана СК; LAS с СК в заголовке | Каждая вершина/точка пересчитывается в ECEF (EPSG:4978) через PROJ, без приближения плоскостью. Годится для протяжённой инфраструктуры. |
| `anchor` | Локальная модель без СК | Тайлы хранятся в локальной системе модели; размещение задаётся широтой/долготой/высотой/азимутом (из `IfcSite`, параметров загрузки или вручную в интерфейсе). |

* СК проекта — EPSG, PROJ-строка (МСК) или WKT. Есть пресеты: WGS 84, UTM 41–45N, СК-42 (Гаусс–Крюгер, зоны 8–15).
* Высоты: Cesium работает с эллипсоидальными высотами. Для нормальных высот
  (Балтийская система) задаётся `height_offset` — поправка геоида.
* Без сервиса рельефа (Cesium ion) глобус поднимается на уровень площадки
  объекта, чтобы подложка, ГИС-слои и модели совпадали по высоте.

## Возможности (что реально работает)

**Фаза 1**
- Авторизация JWT, организации, роли (admin / owner / editor / viewer), изоляция проектов.
- Загрузка и просмотр BIM (IFC 2x3/4/4.3) в браузере без плагинов; выбор элемента, свойства и psets.
- Облака точек LAS/LAZ/E57/XYZ с LOD-стримингом; mesh/фотограмметрия OBJ/PLY/GLB/glTF и готовые 3D Tiles.
- 2D/ГИС: GeoJSON, KML/KMZ, DXF, GeoPackage, Shapefile, GeoTIFF; просмотр атрибутов по клику.
- Измерения: координаты точки (WGS 84 и СК проекта), расстояние (3D / горизонтальное проложение / Δh),
  площадь (в плане и поверхности), перепад высот и уклон, угол, объём насыпи/выемки.
- Аннотации (замечания) с привязкой к точке и к элементу (GlobalId).
- Версии моделей и поэлементное сравнение по GlobalId (добавлено / удалено / геометрия / свойства), цвет в 3D.
- Временная шкала съёмок (по дате съёмки), разбивка по классам IFC и этажам, поиск элементов.
- Сечения (горизонтальное по отметке и вертикальный разрез), режим «План 2D» (ортогональная проекция сверху),
  прозрачная земля для подземной части.
- Документы ПД/РД: загрузка, версии, поиск (название, шифр, имя файла), привязка к элементам.
- Интеграция Autodesk ACC / BIM 360: вход через Autodesk, обзор хабов/проектов/папок, импорт в один клик,
  RVT → IFC через Model Derivative, автообновление новой версией по вебхуку.
- Адаптивный интерфейс для телефона/планшета (браузер).

## Ограничения и что не сделано

Честно, относительно ТЗ:

- **Проверено на синтетических данных**, не на реальных моделях заказчика. Демо-набор генерируется
  `apps/api/scripts/make_demo_data.py`. Критерии «500 МБ < 20 с», «1 ГБ облако» не измерялись —
  для этого нужны реальные файлы и стенд.
- **Autodesk APS** проверен против мок-сервера по официальной документации, без реальных ключей.
  Перед продуктивом нужен прогон с тестовым хабом ACC. RVT при конвертации уходит в облако Autodesk —
  учитывать требования о локализации данных (Закон РК № 94-V).
- **Двусторонняя синхронизация Issues/RFI с ACC и Autodesk Forma** не реализованы.
- **DWG** — только через APS; **ECW** не поддерживается (нужна лицензия Hexagon ECW SDK);
  **FBX** — экспортируйте в glTF/OBJ; **PTX** — нет.
- **Большие IFC**: тайлинг пространственный, но без упрощённых LOD для дальних планов;
  модель целиком загружается в память конвертера. Для моделей в сотни МБ нужен отдельный воркер с запасом RAM.
- **Большие mesh**: один тайл без LOD. Для фотограмметрии рекомендуется загружать готовый 3D Tiles ZIP
  из Metashape/Pix4D/ContextCapture.
- **Облака точек**: октодерево в Python — сотни миллионов точек будут обрабатываться долго (десятки минут).
  Для продуктива вынести в отдельный воркер или подключить PDAL/Entwine.
- **Фоновые задачи** выполняются в процессе API (BackgroundTasks), без очереди. Для нагрузки — Celery/RQ.
- **Высоты**: модель геоида не подключена, только ручная поправка `height_offset`.
- **Растровые подложки** — один PNG без пирамиды тайлов (большие ортофото будут уменьшены).
- **Мобильное приложение** (push, фотофиксация с GPS) и всё из Фаз 2–3 (наложение план-факт с картой
  отклонений, 4D-график, предписания, CV/ML, IoT, 1С) — не начато. Ядро для них готово: облака точек и BIM
  уже в одной системе координат в ECEF, что нужно для карты отклонений.

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/projects/{id}/files` | Загрузка; `category` = `bim` / `point_cloud` / `reality_mesh` / `map_vector` / `map_raster`, `options` — JSON (crs, georef_mode, longitude, latitude, height, heading, height_offset, up_axis, captured_at, replaces_asset_id, name) |
| GET | `/api/projects/{id}/assets` | Слои сцены (3D Tiles) |
| PATCH / DELETE | `/api/assets/{id}` | Привязка (anchor / offset_enu), имя, дата; удаление |
| GET | `/api/assets/{id}/tiles/{path}` | Раздача tileset.json и тайлов |
| GET | `/api/assets/{id}/elements`, `/elements/{globalId}` | Поиск и свойства BIM-элементов |
| GET | `/api/assets/{id}/compare?other=` | Сравнение версий |
| GET/POST | `/api/projects/{id}/annotations` | Замечания |
| GET/POST | `/api/projects/{id}/documents`, `/api/documents/{id}/versions`, `/links` | Документы ПД/РД |
| GET | `/api/crs/resolve`, `/api/crs/presets` | Системы координат |
| … | `/api/integrations/autodesk/*`, `/api/projects/{id}/autodesk/imports` | Autodesk ACC |

Полная схема — `/docs` (Swagger) работающего API.

## Настройка

| Переменная | Назначение |
|---|---|
| `NEXT_PUBLIC_CESIUM_ION_TOKEN` | Рельеф Cesium World Terrain (необязательно) |
| `APS_CLIENT_ID`, `APS_CLIENT_SECRET` | Приложение Autodesk APS |
| `APS_CALLBACK_URL` | `https://<api>/api/integrations/autodesk/callback` (зарегистрировать в APS) |
| `APS_WEBHOOK_URL`, `APS_WEBHOOK_SECRET` | Публичный адрес вебхука и секрет подписи |
| `PUBLIC_WEB_URL` | Куда возвращать пользователя после входа в Autodesk |

Существующая база (созданная до появления двойника) обновляется вручную:
`psql "$DATABASE_URL" -f infra/db/twin.sql` (скрипт идемпотентный).
